## 📦 Модуль 1: Ядро `net/http` и первый сервер

### 🎯 Цель
Научиться поднимать веб-сервер на чистом Go, понимать, как запрос «путешествует» внутри приложения, и уметь корректно завершать работу сервера.

---

### 📚 Ключевые темы (с пояснениями)

#### 1. `http.ListenAndServe`, `http.Server`, таймауты
- **`http.ListenAndServe(addr, handler)`** — самая простая команда для запуска сервера.  
  👉 *Простыми словами:* «Слушай такой-то адрес и обрабатывай запросы вот этим обработчиком».
- **`http.Server`** — более гибкий способ настройки сервера. Позволяет задать:
  - `ReadTimeout` — сколько ждать, пока клиент пришлёт запрос (защита от «медленных» клиентов)
  - `WriteTimeout` — сколько ждать, пока сервер отправит ответ
  - `IdleTimeout` — сколько держать открытым соединение без активности
  > 💡 **Важно:** без таймаутов злоумышленник может «подвесить» сервер, отправив много медленных запросов.

#### 2. Интерфейсы `http.Handler` и `http.HandlerFunc`
- **`http.Handler`** — интерфейс с одним методом: `ServeHTTP(w, r)`.  
  👉 *Простыми словами:* «Любой объект, который умеет отвечать на запрос, — это обработчик».
- **`http.HandlerFunc`** — функция-обёртка, которая позволяет использовать обычную функцию как обработчик.
  ```go
  // Пример: функция становится обработчиком
  func myHandler(w http.ResponseWriter, r *http.Request) {
      fmt.Fprintln(w, "Привет!")
  }
  http.HandleFunc("/", myHandler) // автоматически превращает функцию в HandlerFunc
  ```

#### 3. Стандартный маршрутизатор `http.ServeMux`
- В **Go 1.22+** появились улучшения:
  - Поддержка методов: `/GET/users`, `/POST/users`
  - Параметры в пути: `/users/{id}` (извлекаются через `r.PathValue("id")`)
- **Плюсы:** не нужно подключать сторонние библиотеки для простых задач.
- **Минусы:** нет продвинутой маршрутизации (группы, регулярки) — для этого позже изучим `chi` или `echo`.

#### 4. Работа с `http.Request` и `http.ResponseWriter`
- **`http.Request`** — всё, что прислал клиент:
  - `r.URL`, `r.Method`, `r.Header`, `r.Body`, `r.Context()`
  - Чтение тела: `json.NewDecoder(r.Body).Decode(&obj)` (не забыть `defer r.Body.Close()`)
- **`http.ResponseWriter`** — через него отправляем ответ:
  - `w.WriteHeader(200)` — статус-код
  - `w.Header().Set("Content-Type", "application/json")` — заголовки
  - `fmt.Fprint(w, "тело")` или `json.NewEncoder(w).Encode(obj)` — тело ответа
  > ⚠️ **Важно:** после вызова `WriteHeader()` или записи тела менять заголовки уже нельзя!

#### 5. Graceful shutdown (корректное завершение)
- Зачем? Чтобы при перезапуске сервер не обрывал текущие запросы.
- Как работает:
  1. Ловим сигнал `SIGINT`/`SIGTERM` через `signal.Notify`
  2. Создаём `context.WithTimeout` на 10-30 секунд
  3. Вызываем `server.Shutdown(ctx)` — сервер перестаёт принимать новые запросы, но дожидается завершения текущих
- **Простыми словами:** «Не выключай свет, пока все не вышли из комнаты».

#### 6. Базовая обработка ошибок и статус-коды
- Всегда проверяйте ошибки: `if err != nil { ... }`
- Возвращайте адекватные статус-коды:
  - `200` — ОК
  - `201` — создано (после POST)
  - `400` — плохой запрос (клиент виноват)
  - `404` — не найдено
  - `500` — внутренняя ошибка (сервер виноват)
- **Совет:** не «проглатывайте» ошибки — логируйте их или возвращайте клиенту понятное сообщение.

### 🛠 Практика (пошагово)

1. **Создайте сервер с 3 маршрутами:**
   ```go
   GET  /health        → {"status": "ok"}
   GET  /users/{id}    → {"id": 1, "name": "Alice"}
   POST /users         → принимает JSON, возвращает созданного пользователя
   ```
2. **Чтение тела запроса:**
   - Используйте `json.NewDecoder(r.Body).Decode(&user)`
   - Проверьте `r.ContentLength`, чтобы не читать бесконечность
3. **Graceful shutdown:**
   - Подключите `os/signal` и `context`
   - Обработайте `SIGINT` (Ctrl+C) и `SIGTERM` (от Docker/K8s)

✅ **Чек-лист завершения модуля:**
- [ ] Сервер запускается и отвечает на 3 маршрута
- [ ] Возвращает корректный JSON и статус-коды
- [ ] Корректно завершается по Ctrl+C без обрыва запросов

### 🛠 Практика

1. **Напишите 4 middleware:**
   - Логгер (выводит метод + путь + время выполнения)
   - CORS (разрешает все домены для разработки)
   - Recovery (ловит панику, пишет в лог, возвращает 500)
   - Auth (проверяет заголовок `Authorization: Bearer <token>`, пока — любая строка считается валидной)

2. **Парсинг + валидация:**
   - Принимайте JSON в `POST /users`
   - Валидируйте через `go-playground/validator`
   - Возвращайте `400` с описанием ошибок валидации

3. **Централизованная обработка ошибок:**
   - Создайте функцию `ErrorHandler(w, r, err)`
   - Она смотрит на тип ошибки и возвращает нужный статус + сообщение

✅ **Чек-лист:**
- [ ] Все запросы логируются с временем выполнения
- [ ] Паника не роняет сервер
- [ ] Валидация возвращает понятные ошибки
- [ ] Контекст с `user_id` доступен в хендлерах и репозитории
